# 화면 개선 기록

## 2026-09-29 방향

매크로에 관심을 갖고 기록 자동화를 시작한 개인 도구라는 목적을 유지한다. 첫 화면은 실제 시연 작업 공간으로 만들고, 원문과 판단을 비교하기 쉽게 한다. 공개본에서 분리한 학습 계획은 다시 넣지 않는다.

- 색: 바탕 #F2F5F5, 종이 #FFFFFF, 본문 #20373E, 강조 #25635B, 보조 #60757B, 주의 #845619.
- 글자: 한글 화면은 맑은 고딕 / Apple SD Gothic Neo, 숫자는 Segoe UI와 tabular-nums. 본문 14~15px, 제목 30px 안팎. 원문은 65자 이내 줄 길이.
- 구조: 상단 두 메뉴, 시나리오와 실행 도구, 처리 상태 요약, 원문 목록과 주간 초안 비교 영역. 모바일에서는 원문 다음 초안 순으로 읽되 바로 이동 링크를 제공한다.
- 초점: 뉴스 유형·검색으로 근거를 찾고, 자동 초안과 현재 검토 점수를 비교한 뒤 저장·재실행한다. 빈 상태·처리 중·오류·보존 성공마다 다음 행동을 안내한다.

```text
매크로 기록 자동화                 초안 검토 | 검증 기록
시작한 계기와 시연 범위             시나리오 선택 / 실행
원문 확인 → 초안 검토 → 수정 보존
뉴스 수 / 듀레이션 / 근거 미입력 / 보호된 수정
원문 목록                         주간 초안 7행
검색 + 유형 필터                  현재 실행·점수·근거
                                  자동값 / 현재값 / 수정·재실행
실행 이력                         단계 로그(접기)
```

검토 후 조정: 큰 소개 배너와 별도의 네 개 통계 카드를 피하고 실제 검토 공간에 면적을 배분한다. 단계 번호는 실제 작업 순서에만 사용한다. 색만으로 점수·경고·보호 상태를 구분하지 않고 문구와 부호를 함께 표시한다.

## 변경 범위

화면과 브라우저 상호작용을 개선한다. 고정 가상 입력, 기존 채점·수정 보존 규칙, 서버의 잠금과 로컬 접근 경계는 유지한다. 원문의 검색·유형 필터는 화면 표시만 바꾸며 점수 집계 입력을 바꾸지 않는다.

## 확인 결과 (2026-09-29)

로컬 서버와 실제 브라우저에서 다음을 확인했다. 기존 동작 검사는 `python -X utf8 verify.py`로 22/22 통과했고, JavaScript 문법 검사도 통과했다. 아래 화면 검사는 자동 회귀 테스트에 포함되지 않은 직접 실행 기록이다.

| 확인 | 결과 |
|---|---|
| 첫 실행 | 빈 화면 안내 → 뉴스 8건·분석 7행, 근거 수치 미입력 3행 표시 |
| 원문 찾기 | 없는 검색어는 0건 안내, 검색 초기화 후 의견 필터는 1/8건, 전체는 8/8건 |
| 점수 변경 | 자동 초안 −1.0과 현재 검토값 +1.5 비교, 저장 직후 재실행 대기 표시 |
| 재실행 | +1.5 유지, 수정 보호 1칸, 뉴스 8건 유지 |
| 범위 오류 시나리오 | 듀레이션 0.7 → +0.5, 커브 −3 → −2.0 |
| 정책 갭 시나리오 | 글로벌 정책 +60bp → 듀레이션 +2.0, 커브 −2.0 |
| 이력과 새로고침 | 최근 결과 복원, 이전 기본 시나리오 선택 시 +1.5와 보존 상태 복원 |
| 키보드 | 상단 탭에서 좌우 화살표로 초안 검토·검증 기록 이동 |
| 검증 기록 | 22/22 통과 표시, 기대값과 실제값 표 조회 |
| 화면 크기 | 1440×1000의 좌우 배치, 390×844의 세로 배치 확인. 모바일 문서 가로 넘침 없음(콘텐츠 폭 375px), 분석표만 가로 스크롤 |
| 브라우저 오류 | 검사 중 기록된 콘솔 경고·오류 없음 |

시각 검토 후 분석표의 고정 배지를 `확정 전 초안`으로 조정했다. 사람이 수정한 뒤에도 `사람 검토 전`으로 표시되는 혼동을 피하기 위해서다. 실제 휴대폰·다른 브라우저·스크린리더 사용성은 아직 확인하지 않았다.
