## 수작업과 자동화 비교

같은 자료의 재사용은 학습효과를 만들 수 있다. 가능하면 비슷한 난이도의 자료 두 묶음으로 순서를 바꾸어 비교하고, 표본 수가 작다는 점을 적는다. 프로그램 실행시간뿐 아니라 원문 검토·오류 수정·최종 확인 시간까지 포함한다.

| 날짜 | 자료 묶음 | 뉴스 건수 | 수작업 전체 분 | 도구 실행 분 | 검토·수정 분 | 수치 오류 | 수정 항목 | 비고 |
|---|---|---|---|---|---|---|---|---|
| 미측정 | | | | | | | | |

순절감 시간 = 수작업 전체 − (도구 실행 + 검토·수정). 음수여도 그대로 기록한다. 가상 자료 측정은 실제 업무 측정과 분리한다.

## 분류 평가 계획

- 초기 20건: 지표·이벤트·의견을 포함하고 사람이 정답과 근거를 작성한다.
- 개발용과 보류 평가용을 분리한다. 평가용을 보고 prompt를 고쳤다면 새 보류 표본을 마련한다.
- 유형 분류 정확도, 원문 숫자 보존, 근거 없는 주장 수, 보류가 필요한데 답한 비율을 각각 기록한다.
- 같은 입력을 반복해 모델 변동도 관찰한다. 작은 표본의 높은 점수를 일반 성능으로 주장하지 않는다.
- 현재 verify.py의 통과율은 프로그램 동작 검사다. 분류 정확도 평가가 아니다.

## 프로젝트 소개 초안

“매크로와 채권시장에 관심이 있어 매일 읽는 뉴스와 주간 판단을 기록하는 자동화를 시작했습니다. AI 코딩 도구의 도움을 받아 반복되는 정리 작업을 줄이고, 직접 검토하며 고친 판단을 보존하는 흐름으로 발전시켰습니다. [실제로 담당한 범위]를 정의·검토했으며, 이번 저장소에는 초안 검증과 수정 보존 동작을 가상 자료로 재현했습니다. 현재 [실제로 끝낸 학습과 구현]까지 수행했습니다.”

대괄호는 본인이 채운 뒤 사용한다. 생성된 코드의 양이나 계획한 기술 목록을 개인 숙련도의 증거로 쓰지 않는다.
