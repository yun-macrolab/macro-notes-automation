# records — 공개한 주간 기록

이 폴더의 `YYYY-MM-DD.json`(그 주 월요일 날짜)이 사이트의 **공개 기록** 탭에 실립니다.
이 저장소는 공개 저장소라서, 여기에 올린 파일은 배포 전에도 누구나 볼 수 있습니다.

## 올리는 법

1. 사이트 → **내 파일** 탭 → 그 주 기록 워크북을 엽니다.
2. **공개본 만들기** → 검사어(실명·학교·회사 등, 한 줄에 하나)를 확인하고 **검사하고 내려받기**를 누릅니다.
   이메일 주소·전화번호·주민등록번호·PC 경로는 따로 적지 않아도 검사합니다. 걸리면 만들지 않고 위치를 알려 줍니다.
3. 내려받은 `YYYY-MM-DD.json`을 고치지 말고 그대로 이 폴더에 올립니다(GitHub에서 **Add file → Upload files**).
   같은 주를 다시 올리면 같은 이름의 파일을 덮어씁니다.
4. 1~2분 뒤 배포가 끝나면 공개 기록 탭에 보입니다.

### 지난 주간을 한꺼번에

1. **공개본 만들기 → 여러 주 한 번에**에서 **파일 여러 개 고르기**나 **폴더째 고르기**를 누릅니다(파일·폴더를 화면에 끌어다 놓아도 됩니다).
2. 주마다 위와 같은 검사를 하고, 통과한 주만 `공개본_시작주_마지막주.zip` 하나로 내려받습니다.
   같은 주 파일이 여럿이면 채점 확정, 그다음 최근 저장한 파일을 씁니다.
   이름이나 그 안 폴더 이름에 복사본·사본·백업·테스트·copy·backup·test가 든 파일, 예전 형식(v1)·주간 날짜(I1)가 없는 파일,
   검사에 걸린 파일은 결과 표에 이유와 함께 건너뜁니다.
3. zip을 풀고 안의 `.json` 파일만 모두 이 폴더에 올립니다. 폴더째 올리면 `records/` 아래에 폴더가 생겨 배포 검사에서 거절됩니다.

### PC에서 자동으로

저장소 폴더의 `Publish-Records.bat`(= `publish_records.py`)이 PC의 주간 기록 폴더를 훑어, 이미 올라간 주와 비교해 바뀐 주만
커밋 하나로 이 폴더에 올립니다(같은 검사·같은 복사본 제외, 지우지는 않음). 진행 중인 주(확정 전)도 바뀌면 올라갑니다.
`Publish-Records.bat -Schedule`로 매일 자동 실행합니다.
설정·토큰 만드는 법은 [README의 '자동으로 올리기 (PC)'](../README.md#자동으로-올리기-pc)를 보세요.

## 실리는 것과 빠지는 것

- 실림: 그 주 날짜의 뉴스(제목·출처·분류·핵심내용), 점수·판정·근거·결론, 메모, FLAG(판정에 쓰는 값)
- 빠짐: 다른 주 뉴스, 숨김 장부 열, 시트 행 번호, 엑셀 문서 속성(작성자 등), 원본 엑셀 파일

## 배포 때 다시 하는 검사

`web/build.py`가 이 폴더를 검사하고, 하나라도 걸리면 배포하지 않습니다(사이트는 이전 상태로 남습니다).

- 파일 이름, 정해 둔 칸과 형식, 그 주 밖의 뉴스
- 이메일 주소·전화번호·주민등록번호·PC 경로
- 저장소 비밀값 `PUBLIC_CHECK_WORDS`에 적은 검사어(선택, 한 줄에 하나). Settings → Secrets and variables → Actions에서 넣습니다.
  검사에 걸려도 공개 로그에는 파일 이름과 위치만 남고 걸린 말은 남지 않습니다.

## 내리는 법

파일을 지우면 다음 배포에서 사이트에서 사라집니다. 다만 저장소의 커밋 기록에는 남으므로,
올리면 안 되는 내용이었다면 커밋 기록까지 지워야 합니다.
