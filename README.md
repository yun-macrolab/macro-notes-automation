# 매크로 기록 자동화 · 초안 검토 시연

채권 금리 관점의 주간 매크로 점검에서 **자동 초안 → 사람 수정 → 재실행해도 사람이 고친 칸은 보존**되는 흐름을 가상 뉴스 8건으로 재현한 로컬 시연입니다. 원본은 2026년 7월부터 쓰고 있는 비공개 파이프라인이고, 이 저장소는 그중 초안 검증·수정 보존·실행 기록 부분만 떼어 냈습니다.

**[매크로 기록 보기](https://yun-macrolab.github.io/macro-notes-automation/)** · 공개한 주간 기록(뉴스 원문·점수·메모)을 누구나 보고, 기록 워크북이 있으면 브라우저에서 직접 열어 봅니다. 공개 기록은 정해 둔 칸만 담아 검사를 거친 JSON(`records/`)이고, 내 파일은 어디에도 올리지 않습니다. 아래 [매크로 기록 보기](#매크로-기록-보기-웹) 참고.

| 구분 | 내용 |
|---|---|
| 실제로 실행 | `engine/` 규칙 모듈의 초안 검증·집계·Excel 저장, 수정 보존, 실행 이력(SQLite)·단계 로그(JSONL) |
| 가상 | 뉴스 8건·기관·수치와 점수 초안(고정 JSON). 원본에서는 AI가 뉴스를 분류하고 초안을 쓰며, 실시간 수집은 원본에도 없습니다(원문 수동 투입) |
| 포함하지 않음 | LLM 호출, 다중 사용자, 분류 정확도·업무시간 절감·투자성과 평가 |

## 시연에서 확인하는 채권 규칙

- **부호**: 뉴스 강도는 `+` = 금리 상방, 분석 점수는 `+` = 금리 하락(듀레이션)·플래트닝(커브) — 서로 반대입니다.
- **하우스 의견은 점수에 더하지 않습니다.** 증권사 의견은 대조용으로만 봅니다.
- **통화정책 행은 방향으로 채점하지 않습니다.** 시장 프라이싱 대비 제 금리 경로의 갭(bp)으로만 채점합니다. 갭 수치가 없으면 초안이 준 점수(예: −1.5)를 버리고 0점으로 두되 중립과 구분해 표시하고, 갭이 +60bp면 듀레이션 +2·커브 −2가 됩니다.
- **사람이 고친 칸은 잠급니다.** 마지막 자동 기입값과 다른 칸은 사람이 고친 것으로 보고, 이후 재실행에서 덮어쓰지 않습니다.

## 검증

```sh
python -X utf8 verify.py
```

이 저장소의 동작 검사 **22개 통과**(검증 환경 Python 3.13.2 / openpyxl 3.1.5) — [검증 결과](evidence/검증결과.md). 정상 처리, 정책·기간 프리미엄 규칙, 점수 범위 보정, 의견 제외, 수정 보존, 중복 추가 방지, 잘못된 입력 거절, 로컬 API 경계, 브라우저가 열어 둔 유휴 연결에도 서버가 멈추지 않는지를 확인합니다. 구현한 동작을 확인하는 검사이며, 분류 정확도·업무시간 절감·투자성과를 잰 것은 아닙니다. main에 올라갈 때마다 GitHub Actions가 이 검사와 기록 읽기·공개본 검사([`web/test_workbook_view.py`](web/test_workbook_view.py), [`web/test_public_record.py`](web/test_public_record.py))를 돌리고, 통과해야 웹 화면을 배포합니다([`pages.yml`](.github/workflows/pages.yml)).

한계: 수치가 없어 0점 처리된 항목은 중립 판단과 구분해 읽어야 하고, 자동값과 같은 값으로 고치면 수정으로 감지되지 않습니다. 세부 조건은 [설계 노트](docs/설계노트.md)에 있습니다.

## 시연 순서

1. `초안 검토`에서 기본 시나리오의 **새 시연 실행**을 누릅니다.
2. 원문 검색과 지표·이벤트·의견 필터로 근거를 찾고, 분석표에서 수치 근거가 없는 항목을 확인합니다. 필터는 표시만 바꾸고 점수에는 영향을 주지 않습니다.
3. 검토 점수를 **+1.5**로 바꾼 뒤 **수정값 저장 → 재실행·보존 확인**을 누릅니다.
4. 뉴스가 **8건**으로 유지되고, 점수 **+1.5**와 **수정 보호 1칸**이 남는 것을 확인합니다.

화면에서 자동 초안과 현재 검토값을 비교할 수 있습니다. `검증 기록`에는 동작 검사 결과가, `지난 시연 기록`에는 로컬 실행 이력이 남습니다. 좁은 화면에서는 원문 아래에 분석표가 이어집니다. [화면 개선 기록](docs/화면개선.md)

## 매크로 기록 보기 (웹)

[yun-macrolab.github.io/macro-notes-automation](https://yun-macrolab.github.io/macro-notes-automation/)은 두 탭으로 나뉩니다. 두 탭 모두 같은 화면으로 그립니다.

- **공개 기록**: [`records/`](records/)에 올린 주간 공개본(JSON)을 누구나 봅니다. 주간을 고르면 주소 끝에 `#2026-09-21`처럼 붙어 그 주를 바로 공유할 수 있습니다. 이 탭만 보는 방문자는 엔진(약 14MB)을 내려받지 않습니다.
- **내 파일**: PC의 v2 기록 워크북(.xlsx)을 열어 봅니다. 읽기만 하고 파일을 고치지 않습니다.

화면에 보이는 것:

- **뉴스 원문**: `News DB`의 날짜·요인·지역·제목·핵심내용·출처·방향·강도·유형. 유형 필터와 검색(내 파일은 기간 필터도). 행을 고르는 규칙(5행부터, '예시' 행 제외)은 `engine/rollup_analysis`와 같습니다.
- **점수**: `Analysis`의 7개 항목 듀레이션·커브 점수(전주 포함), 태그, 근거, 뉴스 참고 점수·요약, 하우스 뷰, 직접 고친 칸. 합계와 판정은 엑셀 수식 값이 아니라 `engine/sheet_v2.read_state`로 다시 계산합니다.
- **메모·결론·FLAG**: 메모 칸(28~34행), 금주 결론(D3), 국면·이벤트 등 FLAG, 복기 포인트(내 점수와 뉴스 참고 점수의 큰 차이).

### 공개 기록 올리기

1. **내 파일** 탭에서 그 주 워크북을 열고 **공개본 만들기** → **검사하고 내려받기**를 누릅니다.
2. 내려받은 `YYYY-MM-DD.json`(그 주 월요일)을 고치지 않고 [`records/`](records/)에 올립니다(GitHub에서 Add file → Upload files). 1~2분 뒤 배포가 끝나면 공개 기록 탭에 보입니다.

지난 주간 파일을 한꺼번에 올릴 때는 **공개본 만들기 → 여러 주 한 번에**에서 파일 여러 개나 폴더를 고릅니다(끌어다 놓아도 됩니다). 주마다 같은 검사를 하고, 통과한 주만 zip 하나로 내려받습니다. 같은 주 파일이 여럿이면 채점 확정, 그다음 최근 저장한 파일을 씁니다. 이름이나 그 안 폴더 이름에 복사본·사본·백업·테스트·copy·backup·test가 든 파일, 예전 형식(v1)·주간 날짜(I1)가 없는 파일, 검사에 걸린 파일은 이유와 함께 건너뜁니다. zip을 풀어 안의 `.json` 파일만 `records/`에 올리면 됩니다. 채점 확정 칸이 생기기 전(자동 초안 도입 전) 파일은 '확정 표시 없음'으로 보입니다.

- **실리는 것**: 그 주 날짜의 뉴스(제목·출처·분류·핵심내용), 점수·판정·근거·결론, 메모, FLAG. 화면에 쓰는 칸만 허용 목록으로 뽑습니다([`web/public_record.py`](web/public_record.py)).
- **빠지는 것**: 다른 주 뉴스, 숨김 장부 열, 시트 행 번호, 엑셀 문서 속성(작성자 등), 원본 엑셀 파일.
- **검사는 두 번**: 내려받기 전에 브라우저가 이메일 주소·전화번호·주민등록번호·PC 경로와 직접 적은 검사어(실명·학교 등, 이 브라우저에만 저장)를 찾고, 걸리면 위치를 알려 주고 만들지 않습니다. 배포 때 `web/build.py`가 같은 규칙과 정해 둔 칸·형식을 다시 검사하고(검사어는 저장소 비밀값 `PUBLIC_CHECK_WORDS`, 선택), 하나라도 걸리면 배포하지 않습니다. 공개 로그에는 걸린 말을 남기지 않습니다.
- **주의**: 이 저장소는 공개라서 `records/`에 올린 파일은 배포 검사 전에도 누구나 볼 수 있고, 사이트와 공개본은 검색엔진에도 잡힐 수 있습니다. 검사는 정해 둔 모양과 직접 적은 말만 찾으므로, 그 밖의 민감한 내용은 올리기 전에 직접 확인해야 합니다. 파일을 지우면 다음 배포에서 사이트에서 사라지지만 커밋 기록에는 남습니다. 자세한 내용은 [records/README.md](records/README.md).

### 자동으로 올리기 (PC)

기존 GitHub CLI 로그인이 있으면 별도 토큰을 만들지 않고 설정할 수 있습니다. 아래 `<주간 폴더>`는 실제 경로로 바꿉니다.

```powershell
python -X utf8 publish_records.py --folder "<주간 폴더>" --pattern "*_????????-????.xlsx" --auth gh --dry-run --yes
python -X utf8 publish_records.py --yes
.\Publish-Records.bat -Schedule
```

설정은 PC의 `.macro-notes/publish.json`에 저장됩니다. `--auth gh`는 실행 때 기존 GitHub CLI 인증을 읽으며 토큰 파일을 새로 저장하지 않습니다. 명시한 패턴은 원본 폴더 바로 아래 파일만 고릅니다. `YYYYMMDD-MMDD` 파일명 날짜를 우선하므로 `I1=TODAY()`의 계산값이 비거나 다른 주로 바뀌어도 원래 주간으로 게시합니다. v2 표식이 지워진 경우 전용 라벨로 확인하며 엑셀 자체는 수정하지 않습니다.

예약은 매일 12:00부터 **6시간 간격**(12:00 · 18:00 · 00:00 · 06:00)입니다. PC가 꺼져 있거나 대기 중이어서 놓친 실행은 켜진 뒤에 돕니다. 그렇게 늦게 돈 날에도 다음 시각이 밀리지 않도록 네 시각을 각각 매일 트리거로 등록합니다(반복 하나로 등록하면 늦게 시작한 시각부터 간격을 셉니다). 중복 실행은 차단합니다. 원본 생성(Claude Code)과 업로드는 별개라 이미 저장된 파일은 Claude 로그인 여부와 무관하게 반영됩니다.

- **보류(실패 아님)**: 엑셀에서 열려 있거나(잠금 파일) 마지막 저장 뒤 **10분**이 안 됐거나 읽는 중 바뀐 파일은 올리지 않습니다. 점수를 고치는 도중의 저장이 공개되지 않게 하려는 것입니다. 예약 실행은 5분 뒤 다시 보기를 3번까지 하고, 그래도 보류면 그 파일의 주만 빼고 나머지 주를 올립니다(파일명 날짜나 I1로 그 주를 알 수 있으면 같은 주의 다른 파일로 대신하지도 않습니다). `publish.log`에 `보류 n개(엑셀에서 열려 있음·저장 직후)`로 남고 실패 표시는 생기지 않으며, 다음 실행에서 다시 봅니다. 직접 돌린 실행과 `--dry-run`·`--out`, 토큰이 없는 실행은 기다리지 않습니다. 화면에는 까닭을 따로 보여 줍니다(`엑셀에서 열려 있음` · `저장 직후(약 n분 뒤부터 올릴 수 있음)` · `읽는 중 바뀜`).
  - 보류한 파일은 공개본을 만들려고 읽지 않습니다(엑셀이 저장하는 순간과 겹치지 않게). 그래서 예전 형식(v1) 파일도 열려 있거나 방금 저장했으면 보류로 셉니다. 파일명에 주간 날짜가 없을 때만 그 주를 알려고 I1 칸을 잠깐 읽습니다. 이름이 복사본·백업인 파일은 보류로 세지 않습니다.
  - 보류는 실패 표시가 없으므로, 엑셀이 비정상 종료하며 남긴 `~$` 잠금 파일은 그 주를 계속 보류합니다. 잠금 파일이 하루 넘게 남으면 로그 줄 끝에 `잠금 파일이 하루 넘게 남은 주: YYYY-MM-DD(n일 전부터)`를 덧붙입니다. 엑셀을 닫았는데도 남아 있으면 그 `~$` 파일을 지웁니다.
  - 저장 시각이 지금보다 2분 넘게 미래로 찍힌 파일(시계가 어긋난 경우)은 저장 직후로 보지 않고 평소대로 읽습니다.
- **실패**: 검사에 걸리거나 읽지 못하거나 주간 날짜가 없는 파일이 하나라도 있으면 아무것도 올리지 않습니다. 오류를 건너뛰고 성공으로 기록하지 않으며 `.macro-notes/publish-error.txt`와 `publish.log`에 남깁니다. 예약 작업에는 실패 시 5분 간격 최대 3회 재시작이 설정되어 있고, 다음 정기 실행에서도 다시 비교합니다. 성공하면 오류 표시를 지웁니다. 보류된 파일을 기다리는 실행이 도는 동안(최대 15분) 직접 돌린 실행은 `다른 업로드가 실행 중입니다`로 끝납니다.

아래는 별도 토큰을 사용하는 경우의 설정 방법입니다.

엑셀을 만드는 예약 작업이 따로 있으면 `.macro-notes/publish.json`의 `source_task`에 그 작업 이름을 지정할 수 있습니다. `-Yes` 업로드는 해당 작업이 실행 중이면 2초 간격으로 30초까지 끝나기를 기다려 보고(원본 작업이 게시를 부른 직후에는 잠깐 실행 중으로 보입니다), 그래도 실행 중이면 게시를 보류하고 로그에 `deferred`로 남깁니다. 이렇게 보류된 실행은 다시 돌지 않고 다음 정기 실행에서 봅니다. 원본 작업의 최종 검증이 성공한 뒤 `.macro-notes/source-done` 파일을 새로 쓰고 `Start-ScheduledTask -TaskName MacroNotesPublish`를 호출하면 완성된 파일이 바로 반영됩니다. 이 표식이 5분 안에 쓰인 것이면 그 실행만 10분 대신 저장 뒤 15초 지난 파일부터 올리고, 올리는 실행이 끝나면 표식을 지웁니다(오래된 표식은 로그에 `묵어 무시`로 남기고 지웁니다). 표식 없이 호출하면 10분 규칙대로 다시 보기를 거쳐 올라갑니다. 업로드 로그와 배포 완료 여부는 별도로 확인합니다.

[`publish_records.py`](publish_records.py)는 PC의 주간 기록 폴더(하위 폴더 포함)를 훑어 공개본을 만들고, 이미 올라간 주와 비교해 **바뀐 주만** 커밋 하나로 저장소 `records/`에 올립니다. 브라우저의 '여러 주 한 번에'와 같은 코드·같은 검사를 쓰고(복사본·백업 파일 제외도 같음), 원본 엑셀은 PC 밖으로 나가지 않습니다. 진행 중인 주(확정 전)도 바뀌면 그대로 올라가 사이트에 '확정 전'으로 보입니다. 저장소의 공개본을 지우지는 않습니다.

1. **GitHub 토큰(한 번)**: GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token. Repository access는 **Only select repositories → macro-notes-automation**, Repository permissions는 **Contents: Read and write**만 줍니다.
2. **처음 실행**: 저장소 폴더의 `Publish-Records.bat`을 더블클릭하고 주간 기록 폴더 경로와 토큰을 붙여 넣습니다. 둘 다 이 PC의 `사용자 폴더\.macro-notes\`에 기억합니다. 주마다 결과(새로 올림·바뀜·그대로·건너뜀과 이유)를 보여 주고, `y`를 누르면 올립니다.
3. **자동 실행**: 명령 프롬프트에서 `Publish-Records.bat -Schedule`(기본 12:00부터 6시간 간격, `-At 07:30 -EveryMinutes 60`처럼 바꿈. 간격이 60분 미만이거나 하루를 나누어떨어지지 않으면 시각마다 따로가 아니라 반복으로 등록하며, 이때는 늦게 시작한 날 그 시각부터 간격을 셉니다). 그 시각에 PC가 꺼져 있었으면 켜진 뒤 실행하고, 노트북 배터리로도 돕니다. 바뀐 주가 없으면 아무것도 하지 않습니다. 실패 기록은 `.macro-notes\publish.log`와 `publish-error.txt`에 남습니다. 끄기는 `Publish-Records.bat -Unschedule`.

미리 보기는 `Publish-Records.bat -DryRun`, 검사어는 `.macro-notes\check-words.txt`(한 줄에 하나)입니다. Fine-grained 토큰은 만료일이 있으니 길게 잡아 두고, 만료되면 `.macro-notes\token.txt`를 지우고 다시 실행해 새 토큰을 넣습니다. 이 토큰은 저장소 파일을 고칠 수 있으므로 다른 곳에 붙여 넣지 말고, PC를 바꾸거나 잃어버리면 GitHub에서 바로 폐기합니다.

### 내 파일

- **실시간 반영**: Chrome·Edge는 고른 파일의 위치를 기억해 3초마다 수정 시각을 확인하고, 엑셀에서 저장하면 몇 초 안에 다시 읽습니다. 다음 방문 때는 '지난 파일 다시 열기'를 한 번 누르면 이어서 봅니다. Safari·Firefox에서는 저장한 뒤 파일을 다시 고르면 됩니다.
- **파일은 밖으로 나가지 않습니다**: 고른 파일은 브라우저 작업 스레드의 메모리에서 [Pyodide](https://pyodide.org) 314.0.7(Python 3.14)이 읽은 뒤 바로 지웁니다. 서버나 이 저장소로 보내는 요청이 없습니다(자동 검사에서 같은 주소의 GET 요청만 나가는지 확인). 공개본도 내 PC로 내려받을 뿐 자동으로 올리지 않습니다. 브라우저에는 파일 위치와 검사어만 기억하며, '닫기'를 누르면 화면 내용과 파일 위치를 지웁니다.
- **구조**: [`web/workbook_view.py`](web/workbook_view.py)(워크북 → 화면 자료) · [`web/public_record.py`](web/public_record.py)(공개본·검사) · [`web/worker.mjs`](web/worker.mjs)(작업 스레드) · [`web/viewer.js`](web/viewer.js)(탭·파일 열기·저장 감지·화면) · [`web/build.py`](web/build.py)(사이트 조립·공개 기록 검사). Pyodide와 openpyxl 3.1.5 휠은 정해 둔 해시(npm sha512, PyPI sha256)와 일치할 때만 싣고, 화면 디자인은 시연 화면의 `static/style.css`를 그대로 씁니다.
- **한계**: 첫 방문은 엔진(약 14MB)을 내려받느라 몇 초 걸립니다. 엑셀이 저장하는 도중에 읽으면 실패할 수 있는데, 이때는 직전 화면을 유지하고 다음 저장 때 다시 읽습니다. 시연 엔진으로 만든 합성 워크북으로 Chromium(데스크톱·모바일 폭)에서 자동 검사했고, 실제 원본 워크북·Windows 엑셀·Safari·Firefox에서는 아직 확인하지 않았습니다.
