# 매크로 기록 자동화 · 초안 검토 시연

채권 금리 관점의 주간 매크로 점검에서 **자동 초안 → 사람 수정 → 재실행해도 사람이 고친 칸은 보존**되는 흐름을 가상 뉴스 8건으로 재현한 로컬 시연입니다. 원본은 2026년 7월부터 쓰고 있는 비공개 파이프라인이고, 이 저장소는 그중 초안 검증·수정 보존·실행 기록 부분만 떼어 냈습니다.

**[웹에서 바로 보기](https://yun-macrolab.github.io/macro-notes-automation/)** · 설치 없이 브라우저 안에서 같은 엔진이 돕니다. 처음 방문할 때 약 14MB를 내려받고, 실행 기록은 그 브라우저에만 남습니다.

| 구분 | 내용 |
|---|---|
| 실제로 실행 | `engine/` 규칙 모듈의 초안 검증·집계·Excel 저장, 수정 보존, 실행 이력(SQLite)·단계 로그(JSONL). 웹 시연은 같은 파일을 브라우저 안 Pyodide로 실행 |
| 가상 | 뉴스 8건·기관·수치와 점수 초안(고정 JSON). 원본에서는 AI가 뉴스를 분류하고 초안을 쓰며, 실시간 수집은 원본에도 없습니다(원문 수동 투입) |
| 포함하지 않음 | LLM 호출, 다중 사용자, 분류 정확도·업무시간 절감·투자성과 평가 |

## 시연에서 확인하는 채권 규칙

- **부호**: 뉴스 강도는 `+` = 금리 상방, 분석 점수는 `+` = 금리 하락(듀레이션)·플래트닝(커브) — 서로 반대입니다.
- **하우스 의견은 점수에 더하지 않습니다.** 증권사 의견은 대조용으로만 봅니다.
- **통화정책 행은 방향으로 채점하지 않습니다.** 시장 프라이싱 대비 제 금리 경로의 갭(bp)으로만 채점합니다. 갭 수치가 없으면 초안이 준 점수(예: −1.5)를 버리고 0점으로 두되 중립과 구분해 표시하고, 갭이 +60bp면 듀레이션 +2·커브 −2가 됩니다.
- **사람이 고친 칸은 잠급니다.** 마지막 자동 기입값과 다른 칸은 사람이 고친 것으로 보고, 이후 재실행에서 덮어쓰지 않습니다.

AI가 쓴 코드는 제가 규칙과 검증 기준을 정하고 결과를 검수하는 방식으로 썼습니다.

## 검증

```sh
python -X utf8 verify.py
```

이 저장소의 동작 검사 **22개 통과**(검증 환경 Python 3.13.2 / openpyxl 3.1.5) — [검증 결과](evidence/검증결과.md). 정상 처리, 정책·기간 프리미엄 규칙, 점수 범위 보정, 의견 제외, 수정 보존, 중복 추가 방지, 잘못된 입력 거절, 로컬 API 경계, 브라우저가 열어 둔 유휴 연결에도 서버가 멈추지 않는지를 확인합니다. 구현한 동작을 확인하는 검사이며, 분류 정확도·업무시간 절감·투자성과를 잰 것은 아닙니다. main에 올라갈 때마다 GitHub Actions가 같은 검사를 돌리고, 통과해야 웹 시연을 배포합니다([`pages.yml`](.github/workflows/pages.yml)).

한계: 수치가 없어 0점 처리된 항목은 중립 판단과 구분해 읽어야 하고, 자동값과 같은 값으로 고치면 수정으로 감지되지 않습니다. 세부 조건은 [설계 노트](docs/설계노트.md)에 있습니다.

## 시연 순서

1. `초안 검토`에서 기본 시나리오의 **새 시연 실행**을 누릅니다.
2. 원문 검색과 지표·이벤트·의견 필터로 근거를 찾고, 분석표에서 수치 근거가 없는 항목을 확인합니다. 필터는 표시만 바꾸고 점수에는 영향을 주지 않습니다.
3. 검토 점수를 **+1.5**로 바꾼 뒤 **수정값 저장 → 재실행·보존 확인**을 누릅니다.
4. 뉴스가 **8건**으로 유지되고, 점수 **+1.5**와 **수정 보호 1칸**이 남는 것을 확인합니다.

화면에서 자동 초안과 현재 검토값을 비교할 수 있습니다. `검증 기록`에는 동작 검사 결과가, `지난 시연 기록`에는 실행 이력이 남습니다(로컬은 `runtime/`, 웹은 그 브라우저의 저장소). 좁은 화면에서는 원문 아래에 분석표가 이어집니다. [화면 개선 기록](docs/화면개선.md)

## 실행하기

저장소 폴더에서 아래 명령을 실행한 뒤 브라우저로 `http://127.0.0.1:8765`에 접속합니다(검증 환경 Python 3.13).

```sh
python -m pip install -r requirements.txt
python -X utf8 app.py
```

Windows 실행 파일, 종료 방법, 포트 변경은 [실행 안내](docs/실행안내.md)를 참고하세요. API 키 없이 동작하며, 입력 기사·기관·수치는 모두 가상입니다.

### 웹 시연은 이렇게 돕니다

- 서버가 없습니다. GitHub Pages가 정적 파일만 보내고, 브라우저 작업 스레드에서 [Pyodide](https://pyodide.org) 314.0.7(Python 3.14)이 `core.py`·`engine/`을 로컬 시연과 같은 파일 그대로 실행합니다. `app.py`가 받던 `/api/*` 요청은 [`web/bridge.js`](web/bridge.js)가 가로채 [`web/web_api.py`](web/web_api.py)로 넘기고, 응답과 오류 문구는 로컬 서버와 같습니다.
- 실행 기록(SQLite)과 합성 워크북은 방문자 브라우저의 IndexedDB에만 저장되고, 새로고침해도 남습니다. 저장소나 다른 서버로 보내지 않습니다.
- 화면 파일(`static/`)은 그대로 쓰고, 조립할 때 정적 사이트에 맞지 않는 경로와 '로컬 서버' 문구만 바꿉니다([`web/build.py`](web/build.py)).
- Pyodide와 openpyxl 3.1.5 휠은 정해 둔 해시(npm sha512, PyPI sha256)와 일치할 때만 싣습니다. `검증 기록` 탭에는 배포할 때 GitHub Actions에서 돌린 동작 검사 결과가 실립니다.
- 한계: 첫 방문은 약 14MB를 내려받고 엔진 준비에 몇 초가 걸립니다. 같은 브라우저에서 탭 여러 개로 동시에 실행하면 나중에 저장한 탭의 기록이 남습니다. Chromium 데스크톱(1280px)과 모바일 폭(390px)에서 확인했고, Safari·Firefox·실제 휴대폰은 아직 확인하지 않았습니다.
